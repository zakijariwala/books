# Chapter template

The fixed shape every chapter takes. A repeatable structure keeps the book
consistent, keeps word count predictable, and — if you have a second layer of
reader — lets you assign each section to the reader it serves (see the layer rule
in `docs/buyer.md`).

Generated by Stage 3 from the frozen TOC, the buyer, and the voice sample. The
sections below are a strong default for a technical-nonfiction book; keep,
reorder, or cut to fit, then set a word budget per section totalling your
per-chapter target.

| Section | Job | Words | Optional? |
|---------|-----|-------|-----------|
| Opening scene | A person, a place, something happening. No definition in the first 200 words. | [n] | no |
| The problem | State it as consequence — money, time, risk — not as mechanism. | [n] | no |
| Core explanation | The mental model, before the vocabulary. | [n] | no |
| Worked example | Where the reader's capability actually gets built. | [n] | no |
| Inside a real organisation | How it plays out in practice, with a first-hand story. | [n] | yes |
| The misconception | The wrong belief the reader holds, corrected. Often carries the chapter. | [n] | no |
| The callback | Reuse an earlier concept or the spine thread, in a few sentences. | [n] | yes |
| Summary | What they can now do. | [n] | no |
| One question for [Monday / the reader] | A concrete thing to ask or try, in their own context. | [n] | no |

**Total target: [PER-CHAPTER] words.**

## Rules that apply to every chapter

- Open on a scene or a decision, never on a definition.
- Mark first-hand material with `<!-- STORY-TODO: what this needs -->`. Invent
  nothing.
- Mark figures with `<!-- FIGURE: one line describing what it must show -->`.
  Draw nothing until Stage 6.
- Reference concepts from `docs/concept-registry.md` rather than re-teaching them.
- Use terms exactly as `docs/terminology.md` defines them.
- Match `voice/sample.md`.
