## How to use Part II

These five scenarios are original. Google's own case studies are copyrighted,
and reproducing them here would be both unlawful and useless, since Google
revises the set. What transfers is the method.

For each: find the constraint sentence, name the services, defend the tradeoff.
Then apply the same three steps to whichever case studies appear in your exam.

## The scenario

Original healthcare provider, exiting a co-location contract. 250 words.

Stack to include: Active Directory, SQL Server, MySQL, Redis, a document store,
containerised applications.

Constraints to state, one of which must be the answer key:

- The existing stack stays as it is. This is a replatform
- Regulated data with a residency requirement
- 99.9% availability
- Low-latency connectivity back to remaining on-premises systems
- Centralised monitoring across environments

## Working the problem

- Where the AD trust lands, and why federation beats rebuilding identity
- Cloud SQL for the relational tiers, and the version constraint that could
  force Compute Engine instead
- Memorystore for the cache
- GKE or Cloud Run for the containers, decided on team capability
- Interconnect sizing against the stated latency requirement
- CMEK and VPC Service Controls for the regulated data

## The tradeoff you defend

Name the option rejected and why. The stack-stays-unchanged constraint kills
every refactor, however much cheaper it would run.
