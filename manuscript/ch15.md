## The scenario

Original online retailer running across on-premises and cloud. 250 words.

Stack to include: a spread of database technology (MySQL, SQL Server, Redis, a
document store), a Kubernetes cluster, file-based on-premises integration over
SFTP and batch ETL, a product web application, an IVR feeding a call centre,
third-party monitoring.

Constraints to state:

- Automatic product metadata generation
- A human must approve catalogue changes before publication
- Cost reduction as an explicit goal
- Compliance obligations
- Scale for seasonal peaks

The human-approval requirement is a governance constraint rather than a
technical one, and it eliminates every fully automated answer. Teach readers to
spot that shape.

## Working the problem

- Consolidating the database sprawl, and which stores justify staying separate
- Replacing SFTP and batch ETL with event-driven ingestion
- Image generation and metadata enrichment, with the review queue
- Where cost reduction actually comes from, which is usually the always-on
